# STEM-03 — auditor de solapamiento de workflows
Ejecutar desde el repositorio: `python sistema-maestro/stem/workflow_overlap.py`. La captura contiene cuatro workflows de los PR piloto Lite #64 y Plus #46, sus blobs Git, SHAs, IDs de corridas/jobs y tiempos de pasos obtenidos de la API de Actions. No contiene secretos ni logs. Los resultados son candidatos, nunca autorización de REUSE ni de cancelar/omitir un gate. La medición suma el mínimo de dos tiempos observados por comando, solo con jobs concluidos exitosamente: segundos de runner potencialmente redundantes, no tiempo de calendario ahorrado. Repetir con nuevas capturas antes de generalizar. No extrapolar a las 27 corridas completas.

Lite: CI usa checkout/setup-node v7 y el acumulativo v4; iguales comandos npm pero entorno declarado diferente. Plus: frontend comparte versiones y comandos, pero conserva auditoría, fixture, guard, artefactos, condiciones y pasos anteriores diferentes; revisar equivalencia efectiva antes de extraer un job común. Backend Plus no se considera equivalente: CI usa pytest -q; acumulativo añade -vv, -ra, duraciones y pytest-timeout con señal. No se elimina cobertura. Se propone reutilizar primero un bloque frontend con las mismas entradas y resultado verificado, manteniendo ambos nombres de gate y las comprobaciones exclusivas.
