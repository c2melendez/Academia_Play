# Migración v2/v3 a v4

v4 reemplaza la normatividad operativa de v2 y v3. Los documentos históricos no prevalecen sobre `CONSTITUCION.md`, `RUNBOOK.md`, `GATES.md` y los contratos publicados.

Se restauran: `APROBAR_DISEÑO`, clasificación de evidencias E1/E2/E3, `SOURCE_MISSING`, distinción DETERMINADO/DEDUCIBLE/AMBIGUO, conflictos entre fuentes y prohibición de forzar mecánicas lúdicas.

Se consolidan gates con nombres estables (`G-ORACLE`, `G-A11Y`, etc.), evitando colisiones históricas de G0-G12.

Primera ejecución: infraestructura solo tras autorización y propuesta pedagógica aprobada; no se crean servicios duplicados. Ejecuciones posteriores: leer GitHub HEAD y continuidad y avanzar desde el módulo pendiente.
